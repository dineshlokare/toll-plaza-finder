1. Project Overview & Objective

The system calculates driving highway routes between any two 6-digit Indian postal PIN codes (e.g. 560064 Bengaluru to 411045 Pune) and identifies all physical toll plazas located on the driving path, their exact geographical coordinates, and cumulative distance from the trip origin.

Benchmark Target: The system is calibrated against highway routes (e.g. NH 48 Bengaluru to Pune) achieving > 85% toll detection accuracy matching Mappls / MapmyIndia benchmarks.

2. Architectural Design

The codebase follows Clean Modular Architecture with decoupled domains:

  • Handler Layer (internal/handler): HTTP JSON validation, CORS, error formatting, structured request logging.
  • Service Layer (internal/service): Core business orchestrator coordinating geocoding, route fetching, spatial projection, and caching.
  • Geometry Engine (pkg/geometry): Pure mathematical algorithms for great-circle distance (Haversine), polyline distance accumulation, cross-track perpendicular distance, and bounding box envelopes.
  • Repository Layer (internal/repository/postgres): PostgreSQL connection management, automatic table migration, spatial B-tree/GiST indexing, and batch upserting.
  • Cache Layer (internal/cache): Redis cache wrapper with graceful fallback.

4. Core Business Logics & Spatial Projection Algorithms

4.1 Indian PIN Code Validation

Enforces strict RFC-compliant validation: must be exactly 6 numeric digits, cannot start with 0, and source PIN cannot equal destination PIN.

4.2 Spatial Bounding Box Candidate Filtering

Rather than scanning all 2,387 records across India, a bounding box is constructed around the route with a 20 km margin:

minLat = min(routePoints.lat) - bufferLat
maxLat = max(routePoints.lat) + bufferLat
minLon = min(routePoints.lon) - bufferLon
maxLon = max(routePoints.lon) + bufferLon

PostgreSQL uses indexed range scans on (latitude, longitude) to filter candidates in < 2 milliseconds.

4.3 Highway Cross-Track Perpendicular Projection

For every candidate toll plaza $T = (\text{lat}_T, \text{lon}_T)$ and each route segment $[P_i, P_{i+1}]$:

// Equirectangular projection parameter t along segment
Δx = (lon_{i+1} - lon_i) × cos((lat_i + lat_{i+1}) / 2)
Δy = lat_{i+1} - lat_i
x_T = (lon_T - lon_i) × cos((lat_i + lat_{i+1}) / 2)
y_T = lat_T - lat_i

t = (x_T × Δx + y_T × Δy) / (Δx² + Δy²)
t_clamped = max(0, min(1, t))

P_proj = P_i + t_clamped × (P_{i+1} - P_i)
d_perp = HaversineDistance(T, P_proj)

// Matched if within perpendicular highway buffer:
isOnHighway = (d_perp ≤ 500 meters)

4.4 Cumulative Distance from Source

When a toll is confirmed on the highway, its distance from the origin is calculated as:

distanceFromSource = cumulativeDistance(P_i) + (t_clamped × segmentDistance(P_i, P_{i+1}))

4.5 Twin-Plaza / Dual Carriageway Deduplication

Opposite carriageway booths or dual listings within 1,000 meters are deduplicated, keeping the first occurrence along the route direction.

5. REST API Specification

POST /api/v1/toll-plazas

Request Body:

{
  "sourcePincode": "560064",
  "destinationPincode": "411045"
}

Success Response (200 OK):

{
  "route": {
    "sourcePincode": "560064",
    "destinationPincode": "411045",
    "distanceInKm": 855
  },
  "tollPlazas": [
    {
      "name": "Navalgund Toll Plaza",
      "latitude": 15.53982,
      "longitude": 75.3614,
      "distanceFromSource": 412
    },
    {
      "name": "Hattargi Toll Plaza",
      "latitude": 16.1824,
      "longitude": 74.4521,
      "distanceFromSource": 540
    },
    {
      "name": "Khedshivapur Toll Plaza",
      "latitude": 18.3412,
      "longitude": 73.8546,
      "distanceFromSource": 828
    }
  ]
}

Error Cases (Matching Specification):

  • {"error": "Invalid source or destination pincode"} (400 Bad Request)
  • {"error": "Source and destination pincodes cannot be the same"} (400 Bad Request)
  • {"route": {"sourcePincode":"110001","destinationPincode":"110002","distanceInKm":4}, "tollPlazas": []} (200 OK)
